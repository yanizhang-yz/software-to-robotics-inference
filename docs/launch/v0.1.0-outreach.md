# v0.1.0 Outreach Copy

## Short Version

Software engineers coming from Java or C backends often lack a practical,
evidence-backed path into modern model inference and robotics.
[v0.1.0](https://github.com/yanizhang-yz/software-to-robotics-inference/releases/tag/v0.1.0)
now verifies M0–M2, including a three-episode PushT run that recorded `0/3`
successes and validates the evaluation and artifact-writing path—not policy
quality. Real-arm work is active and supervised; autonomous SO-ARM101 behavior
has not been demonstrated. Please reproduce the
[M1 benchmark on Linux CPU](https://github.com/yanizhang-yz/software-to-robotics-inference/issues/10)
or critique the
[M0 → M1 path from a Java or C background](https://github.com/yanizhang-yz/software-to-robotics-inference/issues/11).

## LinkedIn Version

Software engineers who know production systems but have only light Python and
machine-learning experience face a fragmented path into model inference and
robotics. Tutorials often hide what was actually run, while portfolio projects
can overstate what their evidence supports.

I published
[software-to-robotics-inference v0.1.0](https://github.com/yanizhang-yz/software-to-robotics-inference/releases/tag/v0.1.0)
as an evidence-first transition path. M0–M2 are verified. One concrete result is
the M2 PushT evaluation: three seeded episodes, `0/3` successes, a 95% Wilson
interval of `0.0–0.562`, and three `low_coverage` failures. That result verifies
the evaluation and artifact-writing path; it does not establish policy quality.

The real-arm capstone is active. Supervised SO-ARM101 bring-up is verified, but
dataset collection, training, deployment, and autonomous evaluation are not.
SGLang serving work is planned, and no SGLang performance result is claimed.

If you work on Linux, please reproduce the bounded
[M1 CPU benchmark path](https://github.com/yanizhang-yz/software-to-robotics-inference/issues/10)
and contribute comparable machine-readable evidence. If your background is
primarily Java or C, please follow and critique the
[M0 → M1 reader path](https://github.com/yanizhang-yz/software-to-robotics-inference/issues/11)
by identifying one unstated Python or ML prerequisite.

## Community Feedback Request

Software engineers with light ML and Python experience need a transition guide
that exposes both runnable evidence and the limits of that evidence. The
[v0.1.0 release](https://github.com/yanizhang-yz/software-to-robotics-inference/releases/tag/v0.1.0)
verifies M0–M2; the M2 PushT run recorded `0/3` successes across three seeded
episodes and verifies the evaluation path, not policy quality. Real-arm work is
active and supervised, and autonomous SO-ARM101 behavior is not demonstrated.

Please help test one specific path:

- Reproduce the
  [M1 benchmark on Linux CPU](https://github.com/yanizhang-yz/software-to-robotics-inference/issues/10)
  and contribute environment details plus machine-readable results.
- Follow the
  [M0 → M1 path from a Java or C background](https://github.com/yanizhang-yz/software-to-robotics-inference/issues/11)
  and critique one unstated Python or ML prerequisite.
