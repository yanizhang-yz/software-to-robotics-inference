# Contribution Routes

Use contribution work to improve a reproducible artifact, not to claim a
milestone is complete. Start with LeRobot because M2 establishes the data and
policy context that makes later serving work meaningful. Consider SGLang after
that context is in place.

## LeRobot-First Routes

Propose a documentation clarification, a minimal reproduction, a dataset or
policy inspection tool, or a simulation evaluation improvement. Keep the
issue or pull request focused on one observed problem, its environment, and a
reproducible command. Preserve data provenance and do not publish restricted
or unsafe robot data.

## SGLang-Second Routes

After completing the relevant LeRobot learning work, propose serving
documentation, a reproducible workload, an observability improvement, or a
well-scoped correction. Connect the work to measured serving behavior without
repeating results that already belong in a committed evidence artifact.

## Contribution Ledger

Record each route in one of these states: `proposed`, `submitted`, `reviewed`,
`merged`, or `closed`. These are contribution states, not milestone statuses.

| Project order | Route | State | Evidence or review link | Reusable lesson |
|---|---|---|---|---|
| 1 | LeRobot | proposed | Add when available | Add after review or evidence exists |
| 2 | SGLang | proposed | Add when available | Add after review or evidence exists |

Update the ledger only with a link that another reader can inspect. A closed
route still has value when its lesson explains the constraint or correction.
